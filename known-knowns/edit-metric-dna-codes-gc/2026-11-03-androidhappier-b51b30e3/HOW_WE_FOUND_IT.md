# How we found it (contributor text, unverified)

The brief was a V3R1T4S run on the bank target edit-metric-dna-codes-gc: give an explicit quaternary DNA code with
minimum edit (Levenshtein) distance d, fixed GC content and the reverse-complement constraint that is strictly larger
than the best published lower bound in a cell not marked exact, against Table 7.1 of Jing Sun's Brock M.Sc. thesis
(E_4^{RC,GC}(n, d, floor(n/2)), lengths up to 9).

- Carrier run: the orbit-graph tabu search (dnae.c) beat several non-exact cells of Table 7.1. Its other cells were
  panelled and packaged separately. For (9,3) the carrier run had a 1011-word code (mode G=0, seed 7), stuck at 1011
  for most of a 1500 s run, set aside unjudged.
- One-cell sibling run for (9,3): a preregistration was frozen first (2026-11-03 19:35:31Z, disclosing that the
  1011-word candidate already existed) with a fixed decision rule: claim the largest code that all four checkers call
  VALID at the end of a bounded push search (at most 30 min, at most 3 concurrent jobs, nice 19).
- The 1011 object was checked first (all four checkers VALID, 60/60 mutations rejected) and regenerated
  byte-identically from its seed, so a fallback above 939 existed before the push.
- What worked: mode G=2 (vertices are orbits of the group generated by the reverse complement and the C<->G swap;
  63224 valid GC-4 words, 15806 orbits, 15084 admissible), seed 103, restart length 20000, target 1100: FOUND k=1042
  at iteration 8159505 (612.7 s of search after about 20 min of precompute on a machine at load average about 100,
  restart 404). Only 37 of its words (up to reverse complement) are in the earlier 1011-word code.
- What fell short: in the same budget G=0 (seed 101, restart 50000) reached 1032 and G=1 (seed 102, restart 20000)
  reached 1026; all three jobs ended at their 1800 s timeout without reaching 1100. The object was written about
  30-31 min after the first push job started, borderline against the "<= 30 min" wording; this was disclosed.
- Checking: the object was checked by four checkers (two Python and one C checker carried over from earlier runs, one
  full-DP Python checker), 60 single-symbol mutations of it were all rejected, then it was handed to a three-skeptic
  panel (reproduce, novelty, criterion), each in a fresh context, then an honesty gate, which confirmed the scope
  quoted in README.md. The reproduce skeptic wrote two checkers of its own (C dynamic program, Python edit balls),
  rejected five corruptions, and its same-seed regeneration matched the original log line for line and gave a
  byte-identical file. The criterion skeptic's exact maximum-clique positive control under the same model gave
  (4,3) = 6, equal to Sun's exact value.
- Novelty: later Brock work (Orth's thesis, Houghten's quaternary edit table, Ashlock-Houghten papers) is either
  unconstrained or GC-only; arXiv:1505.06262 has no numeric (9,3) edit value with these constraints; the
  Hamming-metric GC+RC tables are a different metric. The Congressus Numerantium journal version, the Orth & Houghten
  CIBCB 2011 full text and the ISIT 2025 full text were not opened.
- The verify-it-yourself checkers use two methods (exact DP distance and explicit edit balls met in the middle); the
  fast checker was written at packaging time because the family's plain-DP checker takes several minutes on 1042
  words.
