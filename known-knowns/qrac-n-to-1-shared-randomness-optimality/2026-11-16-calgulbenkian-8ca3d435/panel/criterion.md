# Criterion skeptic report

## What I checked
- The criterion (a) asks for a rigorous, independently re-checkable proof that the maximum over unit vectors v_1..v_4 in R^3 of 1/2 + S/(4*2^5) is at most 0.741481 + 1e-6. The accepted forms are interval-arithmetic branch-and-bound with a posted cover, an exact SOS certificate, or a machine-checked proof. The package supplies the first: a posted cover plus a verifier.
- Quantity. The package maximises 1/2 + (1/128) sum over x in {+-1}^4 of ||sum x_i v_i||. That equals S/(n 2^(n+1)) with n = 4, so it is the criterion's quantity. The domain is all four vectors on S^2, which is the full problem. The Bloch-vector reduction and the extreme-point step (norm is convex, so the maximum sits on the sphere) are cited from the Ambainis-Leung-Mancinska-Ozols paper, arXiv:0810.2937, and are standard. They match the target statement, which itself says "the problem reduces to choosing n unit vectors".
- Hidden narrowing. The only reduction is the symmetry reduction (Theorem 1 in proof_qrac4.md). It uses permutations, sign flips and O(3), which are genuine invariances of p. I re-derived the construction in numpy: 20,000 random and degenerate configurations (some with v_k = +-v_1) were mapped to the canonical domain F. In every case p was preserved and all of C4 to C9 held, with 0 failures. The reduction therefore does not lose cases. The root box [-1,1]^2 x [0,1] x [-1,1] x [0,1] covers F, as the proof argues.
- Rigour. I ran the verifier unchanged in a fresh venv with mpmath (python -I). It printed PASS with 43,476 leaves (10,914 symmetry-excluded, 32,152 AM-GM, 410 quadratic, 0 star), and the maximum certified upper bound was 0.741481799559635048. The runtime was about 69 s. The certificate hash matches the one in the claim (8ca3d435...). I read the code for the symmetry leaves (S4-S9). Each uses a strict outward-rounded interval inequality (lower end greater than upper end), which is sound even with interval overestimation. I also read the AM-GM leaf. It builds a rho-weighted upper bound L and a 2nd-order Taylor bound with enclosed Hessian entries. It uses rho > 0 chosen from floats, which is fine because any positive rho is valid. The derivative and cross terms match the algebra in Theorem 2. The Q-leaf code checks smoothness (q_s lower end > 0) and an interval LDL^T positive-definiteness check. The code is sound by inspection, but I did not audit every line of the roughly 900-line script.
- Null model and sanity. A 300-start BFGS run gave a maximum of 0.74148145655, which agrees with the claimed optimum 1/2 + (1+sqrt 3)/(8 sqrt 2) = 0.7414814566. The certified bound 0.7414818 is 3.4e-7 above it, so there is no contradiction and no suspiciously loose or impossible bound. The verifier's calibration values (n = 2 gives 0.853553, n = 4 gives 0.741481) also reproduce.
- The thresholds line up: 0.741481799559635 is at most 0.741482 = 0.741481 + 1e-6.

## Limits and caveats
- Not a machine-checked proof. It is a posted-cover interval proof, but that is exactly one of the criterion's listed forms, and the criterion's verification method names a re-run with an independent implementation. I re-ran the package's own verifier, not an independent Arb implementation. I did, however, independently check the symmetry-reduction step and the optimum value.
- Mild point: the Q-leaf and AM-GM Taylor bounds use midpoint-gradient bounds computed in the same script. They look correct, but a second independent implementation was not written.
- Novelty and the review rule ("a tie is not a record", "follows from a merged package by restriction") are outside my brief. The claim is an upper bound that is new relative to the 0.75 known bound according to the claim file, and I did not search the literature. The NOVELTY skeptic must settle whether an equal or better upstream result already exists. Note also that the n = 4 value 0.741481... was already a known lower bound, so this proof is the new part, not the value.
- This is a full criterion (a) win, not a partial win. It covers n = 4 only and is not an optimality proof for n >= 5 (the package says so itself).
