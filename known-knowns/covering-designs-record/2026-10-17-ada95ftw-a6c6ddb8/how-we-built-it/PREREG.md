# PREREG (written Sat Oct 17 13:05:18 UTC 2026, before any attack output)

## Criterion (verbatim, bank covering-designs-record)
Success means b blocks, each a k-subset of a v-set (no repeated points), covering every t-subset (checked exhaustively), where b is STRICTLY SMALLER (direction: min) than EVERY one of the following, each re-fetched at verification time: the live coveringrepository.com plain (v,k,t) value (m=t section, https://coveringrepository.com/), the live LJCR value (https://dmgordon.org/covering-designs/), and the dmgordo/LJCR GitHub/Zenodo value. It must also beat any value found by grepping GitHub/arXiv for that (v,k,t) over the last 6 months, including unverified hobbyist claims (e.g. thebrockchain/covering-designs: C(28,13,4) <= 53, C(32,13,4) <= 95). If a live table cannot be fetched, the claim is 'PENDING TABLE CHECK', not a record. Parameters must be within v <= 99, k <= 25, t <= 8, and b must be at least the Schonheim bound L(v,k,t); going below it means a bug. Same-day claim only if C(v,t) <= 5e9, so the exhaustive coverage check runs on a laptop; larger cases are logged as 'PENDING chunked exhaustive check' and claimed only after that full check completes.

- p1: A lottery-design record: an explicit (v,k,t,m) lottery covering (every m-subset of the v-set meets some block in at least t points, checked exhaustively) with strictly fewer blocks than the live coveringrepository.com lottery-table value for those parameters and any value found on GitHub/arXiv for them.
- p2: A new exact lower bound: a certified proof that C(v,k,t) is strictly larger than both the Schonheim bound and every lower bound listed for that cell in the live repositories or literature, for some in-range (v,k,t), delivered as a re-checkable certificate (a DRAT proof checked with drat-trim, or an exact ILP infeasibility certificate re-verified by an independent solver).

## Statistic / checker
- Upper-bound lens (structured, PSL/PGL orbit covers): the number b of unique blocks of an explicit design that tools/checker.py reports covers_all=True. Screen: b < coverdata.json size for that cell (snapshot). A screen hit is a candidate only; it becomes a claim only if b is strictly below the live coveringrepository.com value read once honestly, otherwise PENDING TABLE CHECK. b < Schonheim => bug.
- Lower-bound lens (obstruction, p2): a refreshed bound R(v,k,t) = max( ceil(v*LB(v-1,k-1,t-1)/k), ceil(v*LB(v-1,k,t)/(v-k)) ) where LB is the best listed lower bound (coverdata low_bd, plus arXiv:2607.23766 C(12,6,4)>=41), computed in exact integer arithmetic. Screen: R > listed low_bd for the cell and R > Schonheim. A screen hit is a candidate only if the live site's printed lower bound for that cell is also below R (else PENDING TABLE CHECK), and the chain's inputs are themselves certified.
- Thresholds: strict inequality only; ties count as nothing.

null_test: not needed because every candidate is an explicit object (design or exact integer inequality chain) checked by a deterministic checker against a table value; no search statistic or "beats chance" claim is made.
