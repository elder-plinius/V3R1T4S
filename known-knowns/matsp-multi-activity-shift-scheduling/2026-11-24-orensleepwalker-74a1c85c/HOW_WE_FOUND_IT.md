# How we found it (contributor text, unverified)

A counting argument (each employee must work a minimum number of minutes and each worked interval covers exactly one task) showed that 94 of the 225 best known values are already optimal, and an LP relaxation over shift shapes gave a lower bound for the rest; on the large instances the best known values sit up to 25% above it. A teammate agent then built a dedicated search: an aggregate model decides how many shifts of each start and length to staff on each day (and, for several tasks, a task envelope with the one-hour minimum run), a CP-SAT packer threads those shifts into individual employees under the rest, workload and working-day rules, a painter assigns tasks within shifts, and a fast simulated annealing polishes the roster. Counting-tight instances needed a variant with convex micro-slopes in the aggregate objective and an exact single-shift dynamic program. Every roster was checked with two evaluators before the claim was frozen.
