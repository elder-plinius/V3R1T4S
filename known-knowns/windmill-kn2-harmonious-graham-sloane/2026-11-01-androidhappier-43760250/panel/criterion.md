## Which branch is claimed
CLAIM.md claims the full criterion, branch (b), for n = 8. So the question is whether all of (b) is met, not whether a partial (p1 or p2) is met.

## Checking each clause of (b)
1. **"no such labeling exists"**: The quantifier is over every injective f: V(K_8^(2)) -> Z_56 whose 56 edge sums are pairwise distinct. The definition in REPRODUCE.md and checkers/check_label.py matches Graham-Sloane 1980 §3. I read it from their paper (Theorem 20 is there). This is not a tree, so the labels must be distinct. With f(c)=0, a labeling is exactly an ordered pair of 8-sets A, B containing 0, with A ∩ B = {0}, each set having 28 distinct pair sums, and the two sum sets disjoint, which here means complementary. All three checks below search this characterization in full. I found no hidden narrowing: there is no bound on labels, no restriction to "nice" sets, and no use of a unit multiplier or an A/B swap.
2. **"exhaustive search by two independent programs"**: checkers/wsearch.c (P1) does nested C backtracking. checkers/mitm.py (P2) builds every set breadth-first in Python and joins on complementary masks. The algorithms and languages differ. I rebuilt and re-ran both: P1 gave sets=449472, solutions=0, nodesB=270416160 (39.6 s). P2 gave sets=449472, distinct_masks=407352, solutions=0 (11.2 s). Both match result/P1_wsearch_n8.txt and result/P2_mitm_n8.txt. Every hash in SHA256SUMS.txt verifies.
3. **"every symmetry reduction used ... justified"**: Only translation is used, plus increasing-tuple enumeration inside each clique. That second step only drops vertex orderings within a clique, which is a relabeling of vertices and not a residue symmetry. REPRODUCE.md justifies both correctly. Translation is sound because injectivity is kept and every sum shifts by -2f(c), which is a bijection of Z_56. I re-ran checkers/brute_n4.py, which searches with no reduction at all: it found 20736 = 48 x 12 x 3! x 3! labelings, matching the 48 ordered pairs in both result/n4_solutions_P1.txt and result/n4_solutions_P2.txt. That is the positive control: the programs do find solutions when solutions exist. P1 also gives the right verdicts for n = 3, 5, 6, 7 (not harmonious, agreeing with Graham-Sloane's odd n and n = 6) and finds solutions for n = 4.
4. **Third check that does not depend on the claim's code (mine, in scratch)**: I wrote a short C program from scratch. It enumerates all C(55,7) lexicographic 7-subsets with no pruning, keeps those where all 28 sums of {0} ∪ S are distinct mod 56, then sorts the masks and binary-searches for each complement with label overlap exactly {0}. Result: sets=449472, every mask has popcount 28, ordered solutions = 0 (4.5 s).
5. **"re-check the latest DS6 edition and the literature"**: Today I fetched the DS6 PDF; it is the Twenty-eighth edition, dated October 30, 2025. Section 2.4 and the Table 2 windmill row say only "m = 2, H? iff n = 4 [1249]; not H if m = 2, n odd or 6 [1249]". Liu [2153] does not exclude n = 8, because 8 = 2^3 has no prime factor ≡ 3 mod 4. Levine (1983) says a harmonious K_n^(2) needs n to be a sum of two squares, and 8 = 2^2 + 2^2, so 8 is not excluded. (One search-engine summary wrongly said 8 is not a sum of two squares. It is.) Graham-Sloane Theorem 20 covers only n = 4, odd n, and n = 6. Web searches turned up no published decision for K_8^(2). The search could not prove that no obscure paper exists, but the standard survey lists n = 8 as open.

## Null models and stretched definitions
- Null model: could a buggy search simply report "0 solutions"? The n = 4 positive control, together with an unreduced brute force that agrees exactly on the count, rules that out for this code path. A trivial impossibility argument also does not apply: the necessary conditions I know of (parity, Liu, Levine) all allow n = 8. Separately, the claim's own extra filters (result/mod_projection_n8.txt, result/mod_multiset_n8.txt) show that obstructions mod 14 and mod 28 already rule out n = 8. That strengthens the proof. It does not mean the result was already known.
- "Independent": P1 and P2 come from the same author and share the f(c)=0 reduction. But the reduction is proved and checked by brute force, the code paths are separate, and my unpruned third program agrees. I accept this as two independent programs for the purposes of the criterion.
- The DRAT/LRAT route is not needed, because (b) also accepts "exhaustive search by two independent programs".
- Not subsumed: no partial win is being dressed up as the full result. This is the n = 8 cell itself.
