## 1. Definition the checker is built from (quoted from arXiv:2601.07336v1, Section 2)

"A domain D is a Condorcet domain if, whenever the preferences of all agents belong to D, the majority relation of any preference profile with an odd number of agents is transitive." "Sen [23] proved that a domain is a Condorcet domain if the restriction of the domain to any triple of alternatives (a,b,c) satisfies a never condition. A never condition can be of three forms xNb, xNm, or xNt ... xNb, xNm, and xNt mean that x is not ranked last, second, or first, respectively, in the restricted domain." "The size of a domain is the number of orders it contains."

## 2. My checker (own C program, written before reading claim/tools/)

What it does, given N and a file (all checks exact, nothing sampled):
1. **Strict format.** Each line must be exactly N decimal tokens with no leading zero, separated by single spaces, ending in '\n', with no other bytes.
2. **Permutation.** Each line must be a permutation of 1..N.
3. **Distinctness.** All orders are copied as N-byte keys and sorted with qsort, and equal neighbours are counted. It also reports whether the input is strictly increasing in numeric lexicographic order, and whether the sorted copy is byte-identical to the input.
4. **Never conditions.** For each of the C(N,3) triples a<b<c, every order sets one bit in an 8-bit mask, with code = 4[pos a < pos b] + 2[pos a < pos c] + [pos b < pos c]. Each code is then decoded to the ranks (top/middle/bottom) of a, b and c. All 9 never conditions (x in {a,b,c}, rank in {top, mid, bottom}) are tested, and a triple fails if none holds.
5. **Second test per triple.** Does the restriction contain a full cyclic triple, L1 = {abc, bca, cab} or L2 = {acb, cba, bac}? These three orders as a 3-voter profile give a majority cycle.

It prints the counts, a histogram of the never conditions that hold, an FNV-1a hash of the 1330 masks (to check determinism), SIZE and VERDICT. The exit code is 0 only if there are no format, permutation, duplicate, never-condition or Latin-square failures.

**A second, independent route.** A separate DFS enumerator of mine reads claim/object/n21_assignment.txt. It checks that the file names all 1330 triples exactly once, each in the form `a b c iNj`. It then lists, in numeric lexicographic order, every order on 1..21 that obeys all 1330 conditions. When the 2nd element of a triple is placed, that triple's pattern is fully determined, and the enumerator checks it then.
