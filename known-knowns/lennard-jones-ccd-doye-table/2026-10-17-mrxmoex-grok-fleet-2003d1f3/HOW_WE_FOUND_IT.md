# How we found it (contributor text)

## (A) Lennard-Jones tables
1. An overnight sweep (2026-10-16/17) followed every CCD LJ table row's own href (N = 2-150, 310-1000), counted atoms, recomputed the LJ energy of the posted coordinates and tight-polished them (L-BFGS-B, gtol 1e-10). Rows were flagged when the atom count differed from N, or when the polished energy differed from the table by more than convergence noise.
2. On 2026-10-17 each flagged file was re-downloaded 3 times, 5 s apart, and re-checked. The same 5 rows reproduced. Four other overnight flags (N = 506, 521, 538, 541; files `*new.TXT`) came from a bug in our own parser: those files use an "index x y z" layout. After fixing it they match the table to < 3e-7, so they are not part of this package.
3. Novelty check: the CCD files were compared byte-for-byte with the original authors' 2004 archive (Nankai), and the energies were looked up in Barron's 2005 tables. Every lower value is published, so this package contains errata only.

## (B) Morse table
1. The same overnight sweep relaxed every Morse points file at the four tabulated rho0 values (3, 6, 10, 14) and flagged 60 (label, rho0) cells. Our first parser had two bugs of the same kind as the LJ 4-column issue in (A). It dropped the `[n]` saddle-index brackets, so tabulated saddle points were compared against minima. It also ignored each points file's first line, which gives the rho0 the coordinates belong to.
2. On 2026-10-17 a separate adjudication pass fixed both bugs and re-ran every flagged cell. It read the `[n]` brackets and used the header rho0 (it agrees with a gradient-based rho* scan to within 1.2e-4 in all 46 files). It tracked stationary points with Newton continuation, L-BFGS continuation and gradient-norm minimisation, and checked Hessian indices against the brackets. Most flags were explained this way. 30 cells were reproduced by relaxing from the header rho0, 1 was convergence noise, and 16 were bracketed saddles: 12 matched both energy and index, and 4 were bracket-consistent but not located exactly, so they are not claimed either way. One cell was a clean data-integrity erratum: 63C at rho0 = 3, a sign typo (+495.356854[1] vs an index-1 stationary point at -495.356853771). The calibration rows behaved as expected: 25A' and 44A gave index-matching saddles, 38B reproduced off-grid, and 32E showed the known file swap (issue #240). Eight cells stayed unresolved (31D, 47A, 66B, 70B, 75B, 147A x3). They are listed only as an open question in the README and are not claimed.
3. A fresh independent re-download (3 times, byte-identical, and the table byte-identical to the adjudication capture) and the stdlib-only repro in `verify-it-yourself/` reproduce the 63C numbers and the index.
4. Novelty: the CCD has no public errata or history page, and the Oxford mirror shows the same cell. We cannot show the typo is unreported, so it is filed as a data-integrity erratum and its novelty is unconfirmed.
