## Literal reading of "every open n" for (3,5)

The criterion names its own arbiter: arXiv 2607.12912 plus a citation search decide what is already proven. I fetched each source once (sha256 equal to table/status_record.md for both):

- arXiv 2607.12912 (v1 is the only version; Chen, Parker, Zerbib, 14 Jul 2026), Theorem 1.2, attributed to Jonsson: chi(KG(n,k)_{s-stab}) = n - sk + s for k >= 2, s >= 4, n >= 2s(k-1)+2. For (3,5) that threshold is 22; Meunier covers n = sk+1 = 16; n = 15 is trivial; Chen covers only even s; Daneshpajouh-Meunier-Mizrahi only k = 2; the paper's own results are s = 3. On this source the open set is n = 17..21, exactly the criterion's "e.g." list.
- Jonsson's manuscript (Wayback copy cited in table/status_record.md). Theorem 1.3 needs an integer t with 2 ≤ t ≤ s/2, so t = 2 is the only choice for s = 5; d = floor(2n/5); with Schrijver's chi(SG^2_{d,3}) = d - 4 it gives chi >= ceil(n(d-4)/d). I recomputed this: 6, 8, 9, 10, 11, 11 for n = 17..22 against n - 10 = 7, 8, 9, 10, 11, 12, and equality with n - 10 for every n from 23 to 31 (and in general, since d > 4n/11 once n > 22). Corollary 1.6's explicit threshold is (s/(2^q eps))(s(k-1)+eps) = 27.5 with q = 1, eps = 1. So on Jonsson's own text n = 17 and n = 22 are not covered and n = 18..21 are; the threshold 22 quoted in arXiv 2607.12912 matches neither of Jonsson's two statements (that paper also says the manuscript is no longer online). The claim's arithmetic is correct.
- Citation search (rerun by me, 2026-11-09): web searches for Meunier's conjecture and s-stable Kneser graph results in 2025-2026 found nothing beyond arXiv 2607.12912 that settles (3,5) for any n in 17..22. Frick (arXiv 1710.09434) covers s = 2, s = 3 for r >= 4, and r > 6s-6 only; Daneshpajouh (arXiv 2509.22026) is about r = 4 hypergraphs. Neither touches r = 2, s = 5, k = 3. The claim folder itself documents only arXiv 2607.12912 and Jonsson, not a wider citation search; that is a documentation gap in the claim, not a blocker, because my rerun found nothing more.

Decision on the reading: I do not adopt the claim's narrowed definition ("open" = {17, 22}) as the criterion's meaning, since the criterion's named source gives 17..21. The pass does not depend on that dispute: the folder certifies every n from 17 to 22. Under the plain reading (17..21) every open n is certified; under the claim's reading ({17, 22}) both are certified; the union 17..22 is certified. The words "not claimed as new" on n = 18..21 are irrelevant to (a), which asks for certification, not a novelty claim. ## The CNF (regenerated by me, not with the claim's code)

I wrote my own generator (in my scratch folder, not part of claim/) from the prose spec in REPRODUCE.md and the arXiv definition (s-stable: min{j - i, n + i - j} >= s for every pair i, j in the set with i less than j): vertices are the 5-stable 3-subsets of [n] in lexicographic order, variables x(v,c) = v*C + c + 1, one at-least-one-colour clause per vertex, one binary conflict clause per edge (disjoint pair) and colour, then units only. C = n - 11. Its output matches every sha256 in object/cnf_sha256.txt for n = 17..22, with vertex counts 34, 60, 95, 140, 196, 264 (equal to (n/3)·C(n-13, 2)) and edge counts 374, 1140, 2850, 6240, 12390, 22814. The claim's tools/gen_cnf.py was not run.

Symmetry breaking: the only units are x(Q_j, j-1) for j = 1..min(t, C), t = floor(n/3), Q_j = {j, j+t, j+2t}. Per n: n = 17 (t = 5): Q_1..Q_5 = {1,6,11}, ..., {5,10,15}, gaps 5, 5, 7; n = 18, 19, 20 (t = 6): Q_1..Q_6 = {1,7,13}, ..., {6,12,18}, circular gaps at least 6; n = 21, 22 (t = 7): Q_1..Q_7 = {1,8,15}, ..., {7,14,21}, circular gaps at least 7. In every case each Q_j is 5-stable, the Q_j are pairwise disjoint (so a clique), and their number is at most C. Fixing distinct colours on a clique is exactly the symmetry breaking the criterion permits; there are no other added clauses (no at-most-one, no ordering).
