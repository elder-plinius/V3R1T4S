# How we found it (contributor text, unverified)

Run 2026-10-18-0839 of a V3R1T4S workspace, proportion 0.50 only (half of each surprise family's cognate sets masked; the smallest training set). Every development choice was made on validation data cut from training-0.50, which is disjoint from test-0.50 (the organisers' splits are nested, so smaller proportions' training files hold the 0.50 test answers and were not used). Eleven systems frozen in the previous run under the same rule were carried in with their freeze hashes verified; six lenses built new ones in parallel. A pre-registered stage-2 rule combined the six and the eight best by validation score (per-item minimum Bayes risk under the scorer's own NED, integer weights fit on the validation split), and one candidate was fixed by validation NED for all three metrics before any test answer was read.

Weight-0 entries: the per-item rule can pick a string proposed only by a weight-0 entry (20 of 18101 items here), so every entry's code is included and every entry was sealed-checked.

What worked (validation NED at 0.50): choosing each family's combination settings on several stacked bands of the training file (broker, 0.2781 to 0.2710), n-best rerankers trained on folds that look like test rows (analogist, classifier), a noisy-channel score of each candidate against the visible sources (correspondence), a copy expert weighted by how often a language pair is identical (transducer), and tone conditioned on the syllable onset (phylo); the per-item combination of the eight best systems then lowered validation NED from 0.2710 to 0.2625.

What failed: per-family settings chosen on a single band or on cross-validation folds (they did not transfer between bands), rerankers trained on nested bands, learned gates between alternative outputs, tree mixtures as an accuracy gain, and target-language n-gram priors. Development-family rows for shared languages helped a lot on validation (kesslersignificance 0.47 to 0.40) but little on the test set.
