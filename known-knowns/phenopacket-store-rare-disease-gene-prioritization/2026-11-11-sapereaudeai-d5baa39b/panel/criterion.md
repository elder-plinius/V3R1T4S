## 2. Recomputation (own code on results/percase.tsv)
- n = 500 cases, 211 PMIDs, every case present in both conditions; no missing groups, no dropped cases; pre_release of every case equals run 1's assignment in inputs/PRE_percase.tsv.
- MRR_C 0.5567, MRR_PRE 0.0798, dMRR 0.4769, share 0.8566; top-1 0.5005 -> 0.0490 (drop 0.4515); top-10 0.6627 -> 0.1417; disease level 0.5484 -> 0.0727. All equal results/summary.json.
- Own bootstraps (different seeds): dMRR over cases [0.432, 0.520], over PMIDs [0.342, 0.622], matching the claimed [0.4325, 0.5181] and [0.3422, 0.6230].
- Per-PMID-averaged MRR (each publication weighted once): 0.695 -> 0.049, same direction.
- Dropping the two largest PMID clusters (52 and 34 cases, both with PRE >= C) raises dMRR to 0.592; the reported number is the less favourable one.

## 3. What the pre-publication clock does and does not isolate
- Held fixed between C and PRE: LIRICAL version and settings, the phenopackets, the ontology (hp.json v2026-06-06; old HPOA ids mapped onto it, at most 94 rows dropped per release), HGNC, mim2gene_medgen, the gene candidate space.
- Changed: the whole HPOA between the pre-publication release and v2026-06-06. That removes the case's own publication's annotations, but also annotations from every later publication, disease entries created later, and curation changes. The design therefore measures an upper-bound-type quantity (performance attributable to annotations added after each case's pre-publication release), not the share due to the case's own publication alone. The package contains no per-case check that the case's PMID is cited in HPOA v2026-06-06.
- Using run 1's flags in inputs/PRE_percase.tsv: 299 of 500 cases have their disease absent from the pre-publication HPOA; they contribute 0.4255 of the 0.4769 drop (89%), with MRR_C 0.713 -> 0.002. The 201 cases whose disease already existed go 0.324 -> 0.196. So the measured drop is mostly "the disease entry did not exist before the paper". That is consistent with the bank's leakage story for novel-disease papers but is not proven to be same-publication annotation case by case.
- The published leave-one-publication-out audit cited as context (arXiv 2609.02473, LIRICAL 2.4.1, 0.1.27, Recall@1 0.4868 -> 0.1724 on 2,227 cases) shows a smaller drop, which fits the reading that the temporal clock removes more than the case's own publication.
- Because the bank itself names this design as the way to quantify p3 ("e.g. by scoring with annotation releases that predate each case's publication"), using it is not a stretched definition. But the confirmed scope must state the measured drop, not an attribution to same-publication annotation alone. The claim sentence does this: it reports the drop under the release swap and does not use the word "explained".

## 5. Null model and baseline record
- N-SF (paired sign-flip) is a valid test of "C and PRE exchangeable". The real dMRR of 0.4769 beats all 400 controls (best 0.1063). In 20,000 of my own random sign-flips, none reached it. It does not test attribution, i.e. "pre-publication" versus "merely an older release". The N2 date-permutation placebo that would test this was declared not run, and the claim says so (null_test.md).
- baseline/README.md: no comparison against a baseline is made or needed for p3. The arXiv value is context only (different case set, design and unit), and claim.md does not compare against it. That is consistent.
- Packaging notes (not blocking): baseline/README.md and null_test.md cite paths outside claim/ (attempts/, work/, data/); the copies in the package are code/ and inputs/. inputs/lirical_data_sha256.txt lists a `shared/hgnc_complete_set.txt` hash (86cc19...) that is not the 2026-06-05 archive actually declared as used (f3051e..., = inputs/hgnc_complete_set_2026-06-05.txt). REPRODUCE.md says the data directory used the archive, and R1 says the current file makes LIRICAL abort, but the hash list should state which file was in the data directory. The v2022-02-14 PRE rerun logs a peak working set of 8228 kB, which looks like a polling miss, not a JVM size; its 67 cases are all present in the output.

## 6. Is the claim sentence wider than the evidence?
- "the 4,247 phenopacket-store 0.1.27 cases whose paper was published after HPO release v2022-02-14": these are run 1's included cases (4,247 of 10,189 included), and "published after" means "an HPO release's published_at strictly precedes the earliest PubMed date". The confirmed scope says "run-1-included".
- "gene-level MRR over 19,274 protein-coding genes": LIRICAL in phenotype-only mode ranks diseases. The gene ranks are the claimant's pre-registered aggregation (max post-test probability over diseases linked by mim2gene_medgen). The disease-level secondary result agrees (0.548 -> 0.073), so the conclusion does not depend on the unit. The confirmed scope names the aggregation.
- "term ids mapped to the v2026-06-06 ontology" is stated. Sample, not corpus, is stated. No causal "explained by" wording. Numbers exact.
- Non-subsumption: p3 has no novelty clause. The closest published audit (LOPO, same tool and release) uses a different design and gets a different number. Whether the temporal design itself is already published is for NOVELTY.

## Verdict
The literal p3 partial win is met for a declared subset. It is a reproducible audit of a pinned reference tool (LIRICAL 2.4.1, pinned data) on a pinned release of this corpus. It uses the bank's own example design, and it releases code, raw tool output and per-case numbers with case and publication-cluster intervals and a passing paired null. The frozen rule was followed. The three amendments came after tool failures, before any score they could decide; the one that came after other groups' outputs existed lowers the headline. The scope is narrower than "the corpus" and narrower than "same-publication leakage alone", and the sentence below keeps it there.

confirmed_scope: With LIRICAL 2.4.1 in phenotype-only mode (pinned data, HPO ontology v2026-06-06 held fixed), on a seeded random sample of 500 of the 4,247 run-1-included phenopacket-store 0.1.27 cases (211 PMIDs) for which an HPO release predates the case's earliest PubMed date, replacing the contemporary HPOA v2026-06-06 by the last HPOA release published before each case's paper (ids mapped to the v2026-06-06 ontology) lowers the MRR of gene ranks over 19,274 protein-coding genes (derived from LIRICAL's disease post-test probabilities via mim2gene_medgen) from 0.5567 to 0.0798 (paired drop 0.4769, 95% bootstrap over cases [0.4325, 0.5181], over publications [0.3422, 0.6230]; 85.7% of the contemporary MRR) and top-1 recall from 0.5005 to 0.0490 (drop 0.4515, cases [0.4050, 0.4965], publications [0.3297, 0.5864]), a drop that beats all 400 paired label-swap controls (best 0.1063) and that measures the effect of all HPOA annotations added after each case's pre-publication release, not of the case's own publication alone.
