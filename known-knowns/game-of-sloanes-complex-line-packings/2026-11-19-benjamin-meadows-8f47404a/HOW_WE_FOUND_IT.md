# How we found it (contributor text, unverified)

Six unattended numerical search jobs ran on Kaggle CPU notebook sessions (4 worker processes each), submitted on 2026-11-17 at about 23:07 UTC and running about 11.2 hours each, over 46 Game of Sloanes rows with 3 <= d <= 7 where our earlier packings or the packings in the open pull requests to the leaderboard repository were near the best known value. The code is how-we-built-it/src/gos_kernel.py; each cell was one job of 20070 s on one worker.

Method: the job polishes every packing it is given for the cell and keeps a pool of the six best; then each iteration makes one candidate by a basin hop (complex Gaussian noise of scale 0.002 to 0.4 on a pool member, then L-BFGS on a log-sum-exp of the squared overlaps at sharpness p rising to 3e4), a fresh random start, a delete move (a (d, n+1) packing with one random vector removed, small noise, descent) or an add move (a (d, n-1) packing plus one random unit vector, small noise, descent); candidates within 2e-3 of the best get a sequential linear-programming polish on the near-maximal overlaps (HiGHS through scipy). Every pool member carries a tag naming how its line started (the seed it came from, or `dele`, `add`, `fresh`), and basin hops inherit the tag, so the log shows which start each improvement descends from.

Inputs of the job for this cell (how-we-built-it/src/job_inputs.json, every file by public URL and sha256; how-we-built-it/src/build_job.py fetches them and rebuilds the exact job): same-cell seeds (5, 36): pull request 17, file 5x36_grai.txt (JosiahPark); pull request 15, file 5x36_djma.txt (djma); pull request 14, file 5x36_sol.txt (dustinmixon); the leaderboard's posted file 5x36_AUTO.txt (the leaderboard's own AUTO entry (creator code `AUTO`: a vector removed from the best known packing for n+1)); (5, 37) packings for delete moves: pull request 17, file 5x37_grai.txt (JosiahPark); pull request 15, file 5x37_djma.txt (djma); (5, 35) packings for add moves: pull request 19, file 5x35_ARC.txt (arhancanli); pull request 18, file 5x35_owhs.txt (owhs). The selection rule: every distinct published packing of the cell (our packing-records file, the leaderboard's posted file, files in open pull requests) as a seed, and the two lowest-coherence (d, n+1) and (d, n-1) packings from the same sources.

Log for this cell (how-we-built-it/src/progress.jsonl): the polished seeds started the job at 0.499312592334 (pr17:5x36_grai.txt). Improvements, in order: basin hops on the `dele` line from 256 s (17 improvements, 0.499304110372 to 0.499201348826). Final coherence 0.499200803655 after 3357 iterations (2237 basin hops, 509 fresh starts, 402 delete moves, 209 add moves).

Where the object comes from: The final file carries the tag `dele`: its line starts with a delete move on the (5, 37) packing of pull request 15 (djma, file 5x37_djma.txt) or its polished copy in pull request 17 (JosiahPark, file 5x37_grai.txt), which holds the same lines in the same order (the job was given both files and draws one at random for each move). A candidate made by that move entered the pool without beating the best at once; a basin hop on it gave the first new best at 256 s (0.499304110372), and later hops on the same line took it to 0.499200803655. The order-preserving comparison in how-we-built-it/src/order_check.txt confirms the descent: with the best-matching column removed, the object scores 1.0e-02 and 1.0e-02 against pr17:5x37_grai.txt and pr15:5x37_djma.txt, against 0.38 to 0.42 for every (5, 36) seed (0 means the same lines, about 0.5 unrelated ones). The object does not descend from any (5, 36) packing. What deletion and a local polish alone give: removing each of the 37 vectors of pull request 15's (5, 37) packing in turn, then a high-sharpness descent with no noise and a sequential linear-programming polish (gos_kernel.py's own routines), gives at best 0.499257635322 (vector 35 removed; median over the 37 removals 0.499454854764); the object is 5.7e-5 lower.

What failed: of the 46 rows in these jobs, 22 ended below their bar; 16 of those 22 descend from another author's packing for the same cell (a polish) and are not claimed. Most of this job's 2746 basin hops and fresh starts did not improve on the pool.

The file is the job's own output, written with 21 significant digits per coordinate. It has not been published before this claim.
