# How we found it (contributor text, unverified)

Six unattended numerical search jobs ran on Kaggle CPU notebook sessions (4 worker processes each), submitted on 2026-11-17 at about 23:07 UTC and running about 11.2 hours each, over 46 Game of Sloanes rows with 3 <= d <= 7 where our earlier packings or the packings in the open pull requests to the leaderboard repository were near the best known value. The code is how-we-built-it/src/gos_kernel.py; each cell was one job of 20070 s on one worker.

Method: the job polishes every packing it is given for the cell and keeps a pool of the six best; then each iteration makes one candidate by a basin hop (complex Gaussian noise of scale 0.002 to 0.4 on a pool member, then L-BFGS on a log-sum-exp of the squared overlaps at sharpness p rising to 3e4), a fresh random start, a delete move (a (d, n+1) packing with one random vector removed, small noise, descent) or an add move (a (d, n-1) packing plus one random unit vector, small noise, descent); candidates within 2e-3 of the best get a sequential linear-programming polish on the near-maximal overlaps (HiGHS through scipy). Every pool member carries a tag naming how its line started (the seed it came from, or `dele`, `add`, `fresh`), and basin hops inherit the tag, so the log shows which start each improvement descends from.

Inputs of the job for this cell (how-we-built-it/src/job_inputs.json, every file by public URL and sha256; how-we-built-it/src/build_job.py fetches them and rebuilds the exact job): same-cell seeds (7, 24): pull request 18, file 7x24_owhs.txt (owhs); our packing-records file (Benjamin Meadows); the leaderboard's posted file 7x24_hlc.txt (Henry Cohn); (7, 25) packings for delete moves: our packing-records file (Benjamin Meadows); pull request 18, file 7x25_owhs.txt (owhs); (7, 23) packings for add moves: our packing-records file (Benjamin Meadows); the leaderboard's posted file 7x23_hlc.txt (Henry Cohn). The selection rule: every distinct published packing of the cell (our packing-records file, the leaderboard's posted file, files in open pull requests) as a seed, and the two lowest-coherence (d, n+1) and (d, n-1) packings from the same sources.

Log for this cell (how-we-built-it/src/progress.jsonl): the polished seeds started the job at 0.329342957522 (pr18:7x24_owhs.txt). Improvements, in order: an add move from 1932 s (1 improvement, 0.329278533998 to 0.329278533998); basin hops on the `add` line from 1990 s (9 improvements, 0.329278480719 to 0.329278474699); a fresh random start from 12926 s (1 improvement, 0.329036074334 to 0.329036074334); basin hops on the `fresh` line from 12941 s (6 improvements, 0.329036067117 to 0.329036058964). Final coherence 0.329036058456 after 2959 iterations (1981 basin hops, 467 fresh starts, 346 delete moves, 165 add moves).

Where the object comes from: The final file carries the tag `fresh`: it descends from a fresh random start of this job (logged at 12926 s, coherence 0.329036074334), followed by basin hops, not from any packing the job was given. The order-preserving comparison in how-we-built-it/src/order_check.txt agrees: the object scores between 4.678e-01 and 5.142e-01 against every input (about 0.5 means unrelated lines; a packing that descends from an input scores a few hundredths or less).

What failed: of the 46 rows in these jobs, 22 ended below their bar; 16 of those 22 descend from another author's packing for the same cell (a polish) and are not claimed. Most of this job's 2448 basin hops and fresh starts did not improve on the pool.

The file is the job's own output, written with 21 significant digits per coordinate. It has not been published before this claim.
