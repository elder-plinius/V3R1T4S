# How we found it (contributor text, unverified)

Six unattended numerical search jobs ran on Kaggle CPU notebook sessions (4 worker processes each), submitted on 2026-11-17 at about 23:07 UTC and running about 11.2 hours each, over 46 Game of Sloanes rows with 3 <= d <= 7 where our earlier packings or the packings in the open pull requests to the leaderboard repository were near the best known value. The code is how-we-built-it/src/gos_kernel.py; each cell was one job of 20070 s on one worker.

Method: the job polishes every packing it is given for the cell and keeps a pool of the six best; then each iteration makes one candidate by a basin hop (complex Gaussian noise of scale 0.002 to 0.4 on a pool member, then L-BFGS on a log-sum-exp of the squared overlaps at sharpness p rising to 3e4), a fresh random start, a delete move (a (d, n+1) packing with one random vector removed, small noise, descent) or an add move (a (d, n-1) packing plus one random unit vector, small noise, descent); candidates within 2e-3 of the best get a sequential linear-programming polish on the near-maximal overlaps (HiGHS through scipy). Every pool member carries a tag naming how its line started (the seed it came from, or `dele`, `add`, `fresh`), and basin hops inherit the tag, so the log shows which start each improvement descends from.

Inputs of the job for this cell (how-we-built-it/src/job_inputs.json, every file by public URL and sha256; how-we-built-it/src/build_job.py fetches them and rebuilds the exact job): same-cell seeds (7, 29): pull request 18, file 7x29_owhs.txt (owhs); our packing-records file (Benjamin Meadows); pull request 14, file 7x29_sol.txt (dustinmixon); the leaderboard's posted file 7x29_oai.txt (Dustin G. Mixon (creator code `oai` on the leaderboard)); (7, 30) packings for delete moves: our packing-records file (Benjamin Meadows); pull request 18, file 7x30_owhs.txt (owhs); (7, 28) packings for add moves: the leaderboard's posted file 7x28_etf.txt (creator code `etf`). The selection rule: every distinct published packing of the cell (our packing-records file, the leaderboard's posted file, files in open pull requests) as a seed, and the two lowest-coherence (d, n+1) and (d, n-1) packings from the same sources.

Log for this cell (how-we-built-it/src/progress.jsonl): the polished seeds started the job at 0.340542893118 (pr18:7x29_owhs.txt). Improvements, in order: an add move from 393 s (1 improvement, 0.340405562728 to 0.340405562728); basin hops on the `add` line from 418 s (3 improvements, 0.340354898875 to 0.340354873437); a delete move from 2229 s (1 improvement, 0.340130517837 to 0.340130517837); basin hops on the `dele` line from 2237 s (17 improvements, 0.340125618418 to 0.340000506274). Final coherence 0.340000455034 after 3995 iterations (2670 basin hops, 604 fresh starts, 480 delete moves, 241 add moves).

Where the object comes from: The final file carries the tag `dele`: its line starts with a delete move on the (7, 30) packing of pull request 18 (owhs, file 7x30_owhs.txt). One delete move on that packing gave a new best (0.340130517837 at 2229 s, after the polish); the basin hops that followed on the same line took it to 0.340000455034. The order-preserving comparison in how-we-built-it/src/order_check.txt confirms the descent: with the best-matching column removed, the object scores 5.4e-02 against pr18:7x30_owhs.txt, against 0.51 for our packing-records file, 0.51 to 0.57 for every (7, 29) seed (0 means the same lines, about 0.5 unrelated ones). The object does not descend from any (7, 29) packing. What deletion and a local polish alone give: removing each of the 30 vectors of pull request 18's (7, 30) packing in turn, then a high-sharpness descent with no noise and a sequential linear-programming polish (gos_kernel.py's own routines), gives at best 0.340110145083 (vector 15 removed; median over the 30 removals 0.344022190272); the object is 1.1e-4 lower.

What failed: of the 46 rows in these jobs, 22 ended below their bar; 16 of those 22 descend from another author's packing for the same cell (a polish) and are not claimed. Most of this job's 3274 basin hops and fresh starts did not improve on the pool.

The file is the job's own output, written with 21 significant digits per coordinate. It has not been published before this claim.
