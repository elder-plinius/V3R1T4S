# How we found it (contributor text, unverified)

Six unattended numerical search jobs ran on Kaggle CPU notebook sessions (4 worker processes each), submitted on 2026-11-17 at about 23:07 UTC and running about 11.2 hours each, over 46 Game of Sloanes rows with 3 <= d <= 7 where our earlier packings or the packings in the open pull requests to the leaderboard repository were near the best known value. The code is how-we-built-it/src/gos_kernel.py; each cell was one job of 20070 s on one worker.

Method: the job polishes every packing it is given for the cell and keeps a pool of the six best; then each iteration makes one candidate by a basin hop (complex Gaussian noise of scale 0.002 to 0.4 on a pool member, then L-BFGS on a log-sum-exp of the squared overlaps at sharpness p rising to 3e4), a fresh random start, a delete move (a (d, n+1) packing with one random vector removed, small noise, descent) or an add move (a (d, n-1) packing plus one random unit vector, small noise, descent); candidates within 2e-3 of the best get a sequential linear-programming polish on the near-maximal overlaps (HiGHS through scipy). Every pool member carries a tag naming how its line started (the seed it came from, or `dele`, `add`, `fresh`), and basin hops inherit the tag, so the log shows which start each improvement descends from.

Inputs of the job for this cell (how-we-built-it/src/job_inputs.json, every file by public URL and sha256; how-we-built-it/src/build_job.py fetches them and rebuilds the exact job): same-cell seeds (7, 31): pull request 18, file 7x31_owhs.txt (owhs); the leaderboard's posted file 7x31_jrr.txt (Juan Román-Roche and Sebastián Roca-Jerat (using FrameOpt, https://github.com/chuan97/frameopt)); (7, 32) packings for delete moves: our packing-records file (Benjamin Meadows); pull request 18, file 7x32_owhs.txt (owhs); (7, 30) packings for add moves: our packing-records file (Benjamin Meadows); pull request 18, file 7x30_owhs.txt (owhs). The selection rule: every distinct published packing of the cell (our packing-records file, the leaderboard's posted file, files in open pull requests) as a seed, and the two lowest-coherence (d, n+1) and (d, n-1) packings from the same sources.

Log for this cell (how-we-built-it/src/progress.jsonl): the polished seeds started the job at 0.349359418703 (pr18:7x31_owhs.txt). Improvements, in order: an add move from 279 s (1 improvement, 0.348977533332 to 0.348977533332); basin hops on the `add` line from 288 s (4 improvements, 0.348977494567 to 0.348977164924); a fresh random start from 1107 s (1 improvement, 0.348864837025 to 0.348864837025); basin hops on the `fresh` line from 1115 s (3 improvements, 0.348862493347 to 0.348861945149); an add move from 1377 s (1 improvement, 0.348518137705 to 0.348518137705); basin hops on the `add` line from 1420 s (16 improvements, 0.348517912431 to 0.348509807624); an add move from 11953 s (1 improvement, 0.348509747670 to 0.348509747670); basin hops on the `add` line from 12217 s (2 improvements, 0.348509572773 to 0.348509549622). Final coherence 0.348509313852 after 3634 iterations (2415 basin hops, 547 fresh starts, 447 delete moves, 225 add moves).

Where the object comes from: The final file carries the tag `add`: its line starts with an add move on the (7, 30) packing of pull request 18 (owhs, file 7x30_owhs.txt). Three add moves gave a new best: at 279 s (0.348977533332), which the replay described below traces to our own (7, 30) packing, and at 1377 s (0.348518137705) and 11953 s (0.348509747670), which it traces to pull request 18's (7, 30) packing; the basin hops that followed on that line took it to 0.348509313852. The order-preserving comparison in how-we-built-it/src/order_check.txt confirms the descent: the object's first 30 vectors score 2.4e-02 against pr18:7x30_owhs.txt, against 0.53 for our packing-records file, 0.54 to 0.55 for every (7, 31) seed (0 means the same lines, about 0.5 unrelated ones). The object does not descend from any (7, 31) packing. Nearly all of the gain is the add move on owhs's (7, 30) packing plus its polish. The job's random draws can be replayed exactly (our replay script is not part of this package; the replay reproduces the logged count of each move type at every 30-minute log line), and recomputing the add move at iteration 218 (pull request 18's (7, 30) packing plus that iteration's random vector and noise, then the descent and a longer polish) gives 0.34850931384, within about 1e-11 of the object; the later basin hops changed the value only in the last digits.

What failed: of the 46 rows in these jobs, 22 ended below their bar; 16 of those 22 descend from another author's packing for the same cell (a polish) and are not claimed. Most of this job's 2962 basin hops and fresh starts did not improve on the pool.

The file is the job's own output, written with 21 significant digits per coordinate. It has not been published before this claim.
