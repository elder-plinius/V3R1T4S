# How we found it (contributor text, unverified)

An unattended search lane (a series of AI coding sessions in Docker containers) worked through the live spherical-codes.org table for d up to 32, with the table values as targets. The (29, 727) cell came from point addition along a chain that starts from a posted code. Our lane took the posted (29, 715) code from https://spherical-codes.org/data/29/715, added 5 points at the deepest holes and polished it (an L-BFGS penalty ramp, then sequential LP) into our own (29, 720) file. Added 5 more to reach (29, 725) at cosine 0.236140651. And added 2 more to reach (29, 727) at 0.236502969458, below the table 0.240054045231 (how-we-built-it/src/hit.log, from the lane log bM14.log lines 84-88).

What failed or was superseded: deleting 2 points from our (29, 729) file stayed above the table (0.24051379). Greedy deletion from our (29, 728) and (29, 731) files did beat the table (0.23727 and 0.23752), but the addition result above replaced them about four minutes later. The lane notes that subtractive seeding generally lands at the donor level and that basin hopping does not move tight posted codes. The lane wrote no notes for the sessions that produced this cell, so this account rests on its logs and session records.
