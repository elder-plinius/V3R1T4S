# How we found it (contributor text, unverified)

Brief: extend Colonna's 1.5e15 verification by the bank's partial win p2 (local depths for a contiguous range up to 1.6e15). CPU-only sieving at 1.5e15 was measured at about 8.6e9 numbers/s (primesieve, 10 threads), i.e. over 3 hours for the 1e14 range before any row work, so the whole pipeline was moved to the GPU: a segmented sieve (big primes mark a 1 GiB odd-number flag window, primes below 262,144 are sieved in 64 KiB shared-memory tiles), prime emission, and the rows recurrence in shared memory (16-bit lanes until all values are below 256, then packed bytes). A numpy re-computation of 4 blocks every 250 windows and primecount anchors at every 500th window check the run. What failed: the first definition of the claim assumed that once owned entries of a row are in {0,2} all later rows are too; a formalist lens showed that this holds only on a shrinking segment, so the run was restarted with a fixed-row (1,280) check; the first GPU run was also slowed several times when the GPU was shared with other work. What worked: the pipeline reproduces primesieve's primes and numpy's depths exactly on small windows and agreed with every independent check. Five lens agents (independent recomputation, formal lemmas, literature, statistics, contrarian tests) found no defect; the formalist lens caused the restart. The panel's first REPRODUCE round failed only on a stale file manifest, which was repaired and re-run by a fresh skeptic (see `panel/gate.md`).
