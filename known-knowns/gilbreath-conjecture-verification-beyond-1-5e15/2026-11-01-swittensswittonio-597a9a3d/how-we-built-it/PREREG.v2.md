# PREREG.v2 (frozen Sun Nov  1 05:39:44 UTC 2026; supersedes the closure wording of PREREG.md, nothing else)
Disclosed change. A formalist lens (attempts/formalist, found by machine check on small cases) showed that one sentence of PREREG.md is false: "every row >= D(c) is then in {0,2} on the owned entries". Row D+1 of the last owned entry reads one entry of the next block, so closure only holds on a shrinking segment. The quantity D(c) itself (smallest k >= 1 with all owned row-k entries in {0,2}) and its computation are unchanged; D(c) is a local depth, and max D(c) alone is NOT a bound.
First GPU run v1 (windows 0-1130, about 2.4 percent of the range, kept in attempts/evaluator/out_aborted_v1, maxima around 700) was aborted and the whole range restarted from window 0 with the added check below; the thresholds below were fixed before any window of the restarted run was computed.
Added frozen check (K* = 1280 < O = 1536): for every block, whether every owned entry of row K* is in {0,2}. Row K* owned entries are valid since K* <= O. If this holds for every block of the contiguous range, then row K* is clean on the whole range and by closure every later row k > K* is clean on the whole range minus its last k-K* entries. Pass condition: unclean blocks = 0. If unclean blocks > 0 the claim is limited to D(c) per block and says so; K* is not changed after seeing results.
All other definitions, integrity checks 1-5, and the null_test statement of PREREG.md stand. Scope reminder: the range starts at 1.5e15, so this is not a statement about d_k(1) and not the full success criterion.
