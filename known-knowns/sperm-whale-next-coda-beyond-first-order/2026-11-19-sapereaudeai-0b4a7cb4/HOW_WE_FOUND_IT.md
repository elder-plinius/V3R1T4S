# How we found it

**Contributor text, unverified.** This is a plain account of the run, not a checked part of the claim. Every
number that matters is in `README.md`, `object/` and `panel/`, and the checker in `verify-it-yourself/` does not
depend on anything written here.

## The brief was to fail

The operator picked this target because it looked like an easy no. Three public attempts had already tried and
come away with little: WhaleLM reported a 22.7% relative perplexity improvement with no absolute values and no
released code, and a sequence of preprints by Sinha and Chavan had gone from +0.2076 bits to -0.0285 (p = 0.955),
then to 0.081 bits with a confidence interval crossing zero, then to 0.188 and back to -0.004. A MOONSHOT with
tractability 1.5 and that history is a reasonable place to look for a clean, well-documented null.

So the run was briefed to expect nothing, told not to chase a positive, and told that a fully specified negative
was an acceptable and useful result.

## What was done differently

Two choices, both made before the freeze.

**Turn-taking was attempted first.** All three earlier attempts had argued about coda *content*: which coda comes
next. The bank's partial win p4 asks a different question - whether the next coda comes from the same whale or a
different one - and nobody had touched it. The data carry a per-recording whale label, and the bank's own pitfall
says those labels are probably per-recording rather than global identities. That pitfall is usually read as a
warning; here it is permission, because labels that are only locally valid are exactly what a speaker-turn
question needs. p4 cleared its bar first and by a wide margin relative to its threshold.

**The reference was taken seriously, in both directions.** The bank's R1 is a bigram over a 50-token alphabet.
It is easy to beat a bigram by adding capacity, so the run built three nested references rather than one - a
repetition-aware twin, then an order-free bag of the stream's earlier codas, then the full model - so that the
answer to "where does the gain come from" was measured instead of asserted. That is what turned a large headline
number into a much smaller honest one: of the 0.531 bits over the twin, only 0.211 is ordered structure beyond a
stream-local reference.

## What failed or had to be corrected

- A draft of `CLAIM.md` described 0.3198 bits as stream context "with no order". That was wrong: 0.0896 of it
  comes from run-length and repeat-rate features, which do depend on order. The CRITERION panellist caught it and
  the text was corrected before anything was packaged. The conditions were unaffected.
- The baseline record claimed that WhaleLM reports only relative perplexity changes and that no in-cell value
  existed. Both were wrong. WhaleLM does plot absolute perplexities under its own tokenisation, and by the time
  the panel looked, another contributor had filed a draft pull request clearing this very criterion. Corrected.
- One author's row of a results table was typed from memory before being generated by script; it was caught and
  the table regenerated.
- The p3 leakage harness crashed on a string identifier column before printing any score. The fix was recorded as
  `PREREG.v2.md` rather than folded silently into the frozen file.
- The run was stopped by its operator before it finished, with the main-claim skeptics and two of the three null
  tests still running. The operator's main session finished the run: the nulls, the gates, the freeze audit, the
  text corrections and this package.
- A background watcher was killed mid-run because the machine ran critically low on memory. The null workers
  survived it. Nothing was lost, because each control is checkpointed as it finishes.

## What we think is actually true

The dialogues file does carry dependence beyond the previous coda; that part looks solid, cleared both thresholds
by roughly ten times their size, and survived 400 null controls by a factor of fifty. But the most likely
explanation is a slowly varying per-recording state - which coda types this group is using, and at what tempo -
with a smaller genuinely sequential part on top, plus turn-taking structure between whales.

That is a weaker and less exciting claim than "sperm whales have syntax", and it is the one the evidence
supports. The single test that would sharpen it is a control that shuffles codas within each recording, keeping
each recording's composition intact. On the Dominica file, the contributor who cleared this criterion first
reported that their own result failed exactly that control, which was the best available reason to think it
mattered.

So it was run, after the gate was already written: 800 controls, in `how-we-built-it/composition-null/`. It says
the smaller genuinely sequential part is real. Destroying the order inside each recording while keeping that
recording's exact multiset of coda records takes the +0.2112-bit ordered component down to +0.0230 on average,
never above +0.0396 in 400 draws. It does not rescue the bigger number: the +0.2302 bits that come from an
order-free bag of the stream's earlier codas are per-recording composition by definition, so the paragraph above
stands as written.

Two things about that control are worth saying plainly, because they are the kind of thing a reader should not
have to dig for. The statistic we pre-registered for it was wrong, and we found out by running it: a shuffle that
destroys order wrecks the twin reference as thoroughly as it wrecks the model's ordered features, so the gain over
that reference goes *up*, not down. Four of 400 controls beat the real headline margin, and on the Dominica file
all 400 did, by a factor of four and a half. None of that is evidence against the result; it is evidence that the
statistic could not measure what we pointed it at. We wrote the correction down, with timestamps, after two
controls and before the remaining 798, and both the wrong statistic and the right one are reported for all 800.

The second thing is about the other contributor's withheld figure. Their Dominica result failed a control of this
family, and ours - run on the same file, same shuffle - passes on the statistic that survives the critique above
(+0.0255 against 400 controls averaging +0.0094, none reaching it) while failing badly on the statistic that does
not. We cannot see their code and are not claiming their number was right. But the most likely reading is that
their control measured the damage to the reference rather than the absence of order, and on that reading they
withheld a result they did not have to.
